# ColloSys product context

<!-- impeccable:product-schema 1 -->

## Platform

web

The workbench is React rendered inside an independent Electron desktop window. The browser entry is for development and comparison; it does not replace the desktop product requirement.

## Users

Small development teams of up to ten members, retaining their own editors, Agents and independent project directories.

## Product Purpose

Understand who changed what, read the associated captured context when evidence exists, inspect actual file differences and checkpoints, and preview and explicitly confirm restoration of one's own work directory.

## Operating Context

Saved manual edits work without an Agent. A local connector captures authorized directories, preserves checkpoints and queues shared activity. The current complete Codecast foundation supplies authentication, project/task/comment data, reactive transport and the desktop workbench. Convex remains the core business backend; early internal operation prioritizes free allowances. Current startup is local-only.

## Capabilities and Constraints

- Preserve proven interaction behavior and engineering while redesigning visual identity and information expression. Reusing complete source is not evidence that every ColloSys flow has a complete frontend.
- Members' files remain independent. Shared activity never automatically applies another person's files.
- Agent attribution and session/checkpoint relations require evidence. Temporal proximity alone is insufficient.
- Local capture, server receipt and off-machine backup are separate facts. Current local server storage is not remote disaster recovery.
- Restore requires a preview, current-state backup, explicit confirmation and stale-preview rejection. Viewing a teammate's history does not grant local restore authority.
- Keep upstream source immutable, preserve provenance and existing uncommitted work, and author owned changes in the integration layer.
- No purchased services, public deployment, tunnels, invitations or paid model execution are authorized by frontend design work.

## Brand Commitments

An original ColloSys product workbench with coherent typography, density, navigation, states and component expression. No marketing website. No full-site replacement before the user selects a working design sample. Cosmetic recoloring alone does not satisfy the brief.

The user subsequently requested one implemented version, explicitly choosing Google Sans and the supplied peanut-shaped logo. Use one consistent icon family from Hugeicons or Phosphor; the current sample selects Phosphor. Layout, typography and purposeful motion must change as well as color. The ColloSys product name remains; the image supplies the graphic identity, not an instruction to rename all product metadata.

## Evidence on Hand

The pinned Codecast source, owned integration source, PLAN.md and local acceptance evidence are available. Historical tests are not a current visual audit. The October 25 frontend source pass confirms that captured messages currently render as individual plain-text events; the full captured-session reading and handoff UI is not established by the existence of upstream ConversationView or backend session APIs.

## Product Principles

- Orient people around members, work, evidence and recovery boundaries.
- Preserve reading position and context during navigation and live updates.
- Use the same terminology and state meanings throughout the product.
- Make experimental content explicit and compare equal information and actions.
- Select a proven sample before standardizing and migrating other pages.
