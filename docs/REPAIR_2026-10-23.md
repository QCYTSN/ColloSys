# 审计修复与核心工作台验收

原始审计保留在 [AUDIT_2026-10-23.md](AUDIT_2026-10-23.md)，其中结论适用于修复前代码及旧安装包。本轮逐项修复十个已复现问题，并补齐持久化工作台。本文记录本地验证范围；公网与完整上游产品对等不在结论内。

## 十项发现的处理

| 发现                 | 实现变化                                                                                               | 验证依据                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| A01 Git 环境污染     | Git 子进程清除继承的路由/配置环境，只对托管仓库使用隔离索引                                            | `integrity.test.ts`：恶意测试环境下原仓库 HEAD/index 哈希保持不变              |
| A02 快照与内容不一致 | 按捕获字节显式写 blob/tree，核对完整路径和对象；旧快照逐字节校验，坏快照保留证据并拒绝恢复，建立新基线 | 全局忽略、属性过滤、CRLF/二进制、大小写重命名、旧坏快照升级回归                |
| A03 共享规则失效     | 规则文件无法安全读取时停止捕获；超限和链接均不静默跳过                                                 | 超大规则文件不会生成可发送检查点                                               |
| A04 JSON 凭证漏脱敏  | 共享补丁及 Agent 消息处理带引号的键和值，包括转义与空格；本地原始字节保持不变                          | 合成测试凭证不进入 outbox；不使用真实密钥                                      |
| A05 改密并发登录     | 新会话插入条件绑定实际验证过的密码版本；改密撤销只在成功更新后执行                                     | 实际账号处理器和隔离 SQLite 中，挂起的旧密码登录无法在改密后创建会话           |
| A06 跨项目状态串写   | 设置按项目/连接程序/身份隔离；请求中止与代次检查；未保存输入不被轮询覆盖                               | 实际浏览器控制延迟，A→B→A；只向当前端点提交正确策略                            |
| A07 旧上传完成新备份 | 不可变上传代次、独立对象键、代次/哈希/大小条件完成；旧上传只清理自身对象                               | 实际 Worker/R2 验证相同及不同内容的旧 PUT 均不能完成新预留；旧对象迁移读删通过 |
| A08 撤权期间仍可发布 | 项目 DO 串行化最终身份校验和发布；协作 SQL 在写入时检查当前权限                                        | 实际 Worker 挂起事件/评论请求后撤权，继续请求被拒绝；移除/授权竞争与重试通过   |
| A09 来源祖先链接     | Codex 预览和采集逐级拒绝链接/目录联接，通过句柄校验文件身份                                            | Windows 实际 junction 测试拒绝祖先路径                                         |
| A10 重新认证不明确   | 分开显示捕获与投递状态；显式重新连接更新凭证；管理程序按工作区串行启动/停止                            | 真正退出/登录后重连，积压事件只出现一次；并发启动和关闭期间创建均正确收尾      |

这些测试覆盖已复现缺陷，不能推出任意竞态或任意凭证格式都已穷尽。快照仍是成功捕获状态，不是每次按键；多个文件的读取及恢复仍不是文件系统级原子事务。

## 工作台补齐及额外复查

实际复用源码与修改见 [FRONTEND_REUSE.md](FRONTEND_REUSE.md)。核心差异包括持久化活动/会话/消息分页、分片检查点完整文件清单、真实 Pierre 语法差异、Markdown、长会话虚拟列表、阅读位置保留、事件深链接、可调详情布局和移动端返回。

新增回归还复现并修复了：超过一页的新活动漏页；后续检查点分片未进入文件名搜索和增量列表；轮询覆盖刚加载的旧任务；旧任务/交接状态未更新；详情读取失败后重试错资源；初次读取期间的新消息/分片被漏掉；改密密码错误误触发退出；撤权再授权时未落库写入被错误确认。测试不是只断言页面存在。

## 升级及尚未验证的范围

- 启动按序应用三个 D1 迁移，第三个迁移保留旧备份对象键；重新执行不会重置新代次。旧坏快照不会被悄悄“修好”后冒充原始状态。原始 SHA 与清单保留，新的基线另存。
- 源码启动与完整本地数据链路可验证。Windows ZIP 包含 Node、依赖和许可；Git for Windows 仍是外部要求。桌面 VBS/PowerShell 入口曾被自动审批拒绝执行，原因仅返回 `blocked by policy`，本轮不绕过或重试该入口。独立安装验证直接启动包内 Node，不能声称快捷方式已验收。
- 没有公网部署、购买、隧道、实际发送邀请或付费模型调用。异地多机、真实十人、TLS、生产资源限制、备份灾难恢复需上线后验证。
- 会话是公开消息采集与上下文交接；不控制远程 Agent、不自动应用队友文件，也未移植 Codecast 全部工具输出/多工作台功能。Delta 私有 UI/后台没有源码依据，未声称复制。
- 单文件 2 MiB、扫描 10,000 文件/100 MiB；备份压缩包 24 MiB、每账号每项目 512 MiB。服务器事件暂不归档；首次实时缓存追赶仍可能随历史长度增长，尚无百万事件性能结论。
- 忘记密码找回、SSO/MFA、签名安装和自动更新未实现。默认本机 R2 仍与电脑同生共灭。普通恢复与解密预览分别保留 10 分钟和 24 小时。
- 本轮依赖审计的生产依赖为 0 项已知漏洞；完整开发依赖树仍有 7 项通告（5 high、2 moderate，涉及现有 Tailwind/PostCSS 构建链）。未进行未经验证的破坏性升级；分发包含构建工具，因此这也是后续发布清理事项。
