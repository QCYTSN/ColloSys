| 列表和阅读区 | 标题、状态、人物、时间、文件数量多处都在 11–13px；只依赖细微字重，首眼缺少主要目标。 | 正文 14/22，主标题 24/32；队列主任务独立 15/22，元信息 12/18；用列组织，避免全部贴标签。 |
| 右侧“保存状态” | 用户能看到已保存/未备份，但容易与任务完成状态混读。 | 在“来源与保存”明确区分任务进展、设备保存、服务确认和异机备份。 |
| 文件详情与长标题 | 多处截断虽然防溢出，却丢失重要文件/任务名；窄窗时上下文大幅退到不易发现的位置。 | 主标题允许自然换行；原文件路径在详情保留；窄窗显式“记录/变更/来源”切换。 |
| 菜单/搜索等行为 | 样例已有可用 Radix 菜单、恢复状态场景、搜索等，不能把外观拒绝误读为要删除成熟行为。 | 新预览独立制作，正式实现的适配留到确认后。 |

不以“文字小、边界浅”作为唯一问题。关键错误是默认阅读顺序没有先回答下一步该做什么。仅修改灰色、阴影、圆角无法解决。

## 正式集成：当前真实能力及缺口

基线脚本 `tests/codecast-design-baseline.mjs` 在本次运行成功读取原先测试账户/工作区，采集四个真实状态，没有写入工作区文件、没有确认恢复。

| 能力 | 实际入口/实现 | 保留要求 / 限制 |
|---|---|---|
| 账户/项目/任务/评论 | 原 Codecast auth、Convex、store、tasks 路由 | 不换后端或复制任务状态；仍由服务端验证成员身份。 |
| 配置本地目录和来源 | `LocalWelcome.tsx`、`LocalWorkspaces.tsx` 与本地 manager | 只有明确选定根目录；采集权限继续显式。 |
| 人工编辑与活动流 | `useCollaboration.ts` feeder → Codecast `colloEvents` / `colloWorkspaces` | 不要求 Agent 才显示活动；分页和重放不能因视觉重构失效。 |
| Agent 消息 | `LocalWorkspaces.tsx` 按捕获事件详情展示 | 当前正式 UI 主要是单条消息；全会话读法、工作项关联需要在 D 真正接通。 |
| 文件变化与完整性 | `collaborationModel.ts` assembleCheckpoint、`LocalWorkspaces` diff | checkpoint 分片完整性是事实，不能从本地已有缓存推断服务器已收齐。 |
| 恢复预览 | Local history → Preview restore → 独立 dialog | 只恢复自己目录；独立预览、当前状态备份、显式确认、拒绝过期预览保持不变。 |
| 本地保存/同步/异机备份 | connector/outbox/backup API | 三者分开；远程限额不应抹掉 pending；不声称当前本地服务等于灾备。 |
| 独立桌面 | Codecast desktop framework + owned Windows adaptation | 本次浏览器候选不是新桌面实现，也不替换默认桌面入口。 |

真实界面当前的主要问题：全局导航展示太多低频上游功能；重复顶栏侵占可读高度；长测试邮箱成为主体；任务/会话/变化之间需要统一可寻址工作上下文。新的 IA 需要基于明确关联，不能用时间相近自动拼接“故事”。
