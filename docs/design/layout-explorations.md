# 两种工作组织方式

阶段 B/C。采用相同字体、颜色、图标和 fixture 比较结构，避免用配色差异掩盖布局相同。

## A：待办驱动 / 交接队列（推荐先验证）

```text
┌ ColloSys   项目选择    工作 / 团队     查找         用户 ┐
│ 需要你处理                                      创建任务 │
│ 待处理 3     进行中 1     所有工作 6        筛选 / 搜索  │
├ 工作                         执行者     原因      更新 ┤
│ ▾ 修复来源归属                林舟/Codex  等你审查     │
│ ▸ 恢复预览边界                你        等待确认      │
│ ▸ 窄窗口导航                  陈一      等你审查      │
│ ┌ 当前问题、处理动作 ────────────┬ 文件变化 ─────────┐ │
│ │ 请求 → 结果 → 折叠执行记录     │ 当前文件 + 逐行 diff│ │
│ │ 评论 / 准备交接               │ 来源与保存入口      │ │
│ └───────────────────────────────┴────────────────────┘ │
└───────────────────────────────────────────────────────┘
```

用户是巡检/协调者：先扫完整待处理队列，再在队列下方阅读当前工作。没有全局侧栏；详情不会插在任务行之间打断队列。当前工作以选中行和下方阅读面关联，其他工作保持可见的一行。

桌面工作面最大 1544px，左右边距 `clamp(24px, 4vw, 64px)`，1920 下多余空间留在边缘。列表行最小 64px；详情为阅读面与变更面，1050px 以下改为“记录/变更”单面切换。详情有内部滚动，默认 1440×900 下约 350px 高；1280×800 下详情底部低于首屏，需要页面滚动。较矮窗口的页面与内部阅读滚动是当前候选的明确代价，未宣称已解决长记录阅读。

**优势**：第一眼知道下一步，完整待处理队列位置稳定；跨任务审查成本低。**代价**：队列占据首屏高度，较矮窗口中的长对话依赖详情内部滚动，不适合连续写作数小时。

## B：当前焦点驱动 / 会话工作面

```text
┌ ColloSys   项目选择       工作 / 团队        查找      ┐
│ 林舟·Codex         你·人工         陈一·Claude Code   │
│ 来源归属 待审查    恢复预览 待确认    目录导航 执行中  │
├ 当前任务标题 ──────────────────────── 准备交接 ──────┤
│ 请求、结果、执行步骤                 │ 关联变更       │
│                                     │ 文件选择       │
│ 连续会话阅读面                       │ diff           │
│                                     │ 来源与保存     │
│ 评论输入                            │                │
└─────────────────────────────────────┴────────────────┘
```

用户是专注在一项任务上的开发者。上方是可横向滚动的活跃工作切换带，当前会话占据主要空间，任务标题和动作共一条水平轴；没有左侧全量活动索引。证据面可关闭以扩展阅读区；新记录在原阅读位置以提示加入，不自动抢滚动。

切换带溢出时横向滚动/查找，不把十名成员挤成十个小块。桌面阅读面与证据面按约 1.55:1 分配；1050px 以下证据转为单独页签，800px 和 600px 以下继续收拢顶部上下文。即使桌面曾关闭证据，缩窄后仍可通过“变更”页签访问。主文与证据各自滚动，长记录表现需在 D 再确认。

**优势**：长会话与代码关系更近，切换时信息模型稳定，适合沉浸审查。**代价**：同一时刻看不到全部待处理原因，超过 4–5 个活跃项需要横向查找；团队巡检不如 A。切换带不能冒充完整 Agent 生命周期管理。

## 比较与推荐

| 判断 | A 交接队列 | B 会话工作面 |
|---|---|---|
| 首眼的问题 | 什么需要我处理 | 我正在审查哪项工作 |
| 主空间关系 | 完整队列在前，选中详情在后 | 横向工作切换带，固定主阅读面 |
| 切任务的代价 | 队列就地选择 | 切换带/查找 |
| 长对话 | 队列占用高度，详情内部滚动 | 更多垂直空间，但仍独立滚动 |
| 10 人团队 | 不需要十列 | 横向切换带会溢出，需要搜索 |
| 小窗口 | 列合并，详情页签 | 证据收为页签，工作带仍可滚动 |

推荐 **A 作为项目进入页**，因为现有核心能力是共享活动、任务评论、变化证据与本地安全恢复，用户首先需要决定哪里该介入。B 是有实质不同取舍的候选，不在确认前擅自把两者拼成更复杂的多面板产品。

设计技能探索 seed `5b8192b0` 已运行，其随机单方向规则由用户明确的“两种结构比较，阶段 C 再选择”要求覆盖。交通翻牌/线路图/倾斜玻璃等候选有实体可识别性，但不能清晰表达任务/会话证据关系，且增加文字动作，因此没有把这些隐喻移植进产品。预览直接以浏览器呈现，不调用付费生图或模型 API。
