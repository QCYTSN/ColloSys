# 信息架构：从需要处理的工作到可信证据

阶段 B，2026-10-26。讨论中的“工作项”是界面投影，不是另建一套后端任务库。

## 用户任务与信息模型

进入时先回答：有没有明确需要我处理的任务/评论/共享失败？其次是团队当前在推进什么。最后才是完整历史。运行状态有直接事件证据时才可称“执行中”；连接正常只表示连接正常。

关系：项目 → 任务 → 明确关联的会话 → 有来源证据的文件变化/检查点。成员和 Agent 是执行者属性。没有关联时，独立活动保持独立，不按时间硬拼到某个任务；人工编辑不归给同时运行的 Agent。

现有事实来自原 Codecast task/comment/session store 与 ColloSys versioned event/checkpoint 协议。前端只做可读投影：`任务进展`、`需要谁处理`、`执行来源`、`同步交付`、`保存/备份` 是五个独立维度。

## 核心流程

1. 打开项目 → 看到待处理事项 → 选择一个工作 → 阅读明确的处理原因 → 查看相关变化 → 写评论或准备交接。
2. 切换至活跃工作 → 选择成员/Agent 的会话 → 看最后已捕获状态 → 展开执行记录。没有执行生命周期数据则显示最后更新时间与“状态未知”。
3. 从文件变化 → 查看来源 → 打开明确关联会话与任务。来源不足时显示“未关联会话”，没有伪造跳转。
4. 从自己的检查点 → 查看本地保存/服务接收/备份 → 进入恢复预览 → 比较影响 → 备份当前状态 → 用户确认。队友检查点没有本地恢复按钮。
5. 断网/限额 → 继续看本地已有内容 → 待发送状态明确 → 恢复连接后原 outbox 补发。当前目录不接收队友文件。

## 始终可见与按需出现

始终：项目定位、当前工作标题/状态、一个主要动作、清晰的当前选中位置。存在问题时：离线/权限/共享失败及可行动下一步。按需：文件树、执行日志、检查点明细、项目管理、备份与配额。不要让“没有备份”成为所有任务上同样醒目的常驻横幅；在用户询问保存/恢复时准确呈现。

采用文字 + 图标 + 少量颜色表达状态。任务待确认 ≠ Agent 等待 ≠ 未同步；任务完成 ≠ 文件已异机备份。UI 不暗示评论发送会直接启动模型；C 中评论是明确标记的本地演示。

## 阶段 C fixture 与正式对接边界

两个候选使用同一组 6 项工作：需要审查的来源归属修复、等待确认的恢复预览、执行中的导航调整、离线待补发的手动编辑、已完成的阅读位置、无 Agent 证据的文案变化。成员为演示成员，任务/会话/文件均为静态合成数据。

评论、已查看和交接仅保存在当前预览内存；刷新重置。过滤与选择不覆盖真实 store。D 才把这一投影映射到现有 task/comment/event ID，补充拒绝访问、事件缺失和分页。不得把 C 的全会话/实时演示计为正式能力完成。
